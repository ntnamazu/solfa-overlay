# 要求内容

- 作業名: 20260718-chord-column-pairing（和音・多声の符頭対付け修正）

## 背景

コードレビュー（2026-07-18）の指摘1（最重要）への対応。

`ScoreModelBuilder.matchStack` は x 昇順の符頭列と MusicXML の文書順音符列を添字で
対付けしている。この方式はプロトタイプ（`solfa_proto.py`）からの忠実な移植であり
Victoria 実測（784音・ミスマッチ0）で成立していたが、以下のケースで対付けが崩れる:

1. **和音**: 同一ステム上の符頭は x がほぼ同値で、sheet XML の head 出現順と
   MusicXML の note 文書順が一致する保証がない。異レターの取り違えは step
   クロスチェックが拾うが、**同レター（オクターブ重複 divisi）は静かに壊れる**
2. **異リズム多声**（backup/forward）: 文書順は声部ごとにまとまる一方、
   版面の x 順は時間順のため、添字対応が原理的に成立しない

ユーザーのレパートリー（混声合唱）では、SSAATTBB の divisi を 4 段（1 段に
2 パート同居）で組む現代曲が頻出するため、多声対応は必須。

## 決定事項（ユーザー選択・2026-07-18）

1. **列の切り出し方**: 貪欲分割（閾値なし）。MusicXML の同 offset 音群を「同時に
   鳴る列」とし、x 昇順の符頭を列サイズどおり先頭から切り出す。x 距離の閾値
   （マジックナンバー）は導入しない
2. **スコープ**: 多声込みで固定。backup/forward の異リズム多声も合成テストで
   挙動を固定する（アルゴリズム自体は offset 列化で構造的にカバーされる）
3. **実フィクスチャ検証**: 本修正の直後に単独の /add-feature として実施
   （ユーザーがホストで Audiveris を手動実行し、Victoria + divisi 曲の出力を提供）

## 要求

### 1. 列対付けアルゴリズムへの変更

- MusicXML 側: 小節内の発音音符を offset でグループ化し「列」とし、offset 昇順に並べる
- OMR 側: x 昇順の符頭列を、列サイズどおり先頭から貪欲に切り出す
- 列内: 符頭は譜表位置（中線=0・下向き正）の昇順（=高い音から）、MusicXML 音符は
  幹音の絶対音高（diatonic index）降順（=高い音から）に並べて対にする
- 小節単位の音符数照合（不一致→skipped + issue）は現行どおり維持する
- step クロスチェックの意味論（step のみ比較）は変更しない

### 2. 符頭中心座標の丸め統一（レビュー指摘3の同梱）

- stack 内包判定（`head.x + head.w / 2`）と NoteEvent 格納値
  （`head.x + Math.trunc(head.w / 2)`）の丸めを `Math.trunc` に統一する

### 3. テストによる挙動の固定

- 和音で文書順と x 順が食い違うケース（異レター）の正対付け
- オクターブ重複 divisi（同レター）の正対付け（旧方式では静かに壊れたケース）
- backup/forward の異リズム多声（列マージ）の正対付け
- ユニゾン共有符頭（1 符頭 vs 2 音）が現状は音符数不一致→skipped になることの明文化

## スコープ外

- **ユニゾン共有符頭の照合緩和**（同 offset・同音高の重複をまとめて数える等）:
  Audiveris の実出力を見てから判断する（証拠なしに照合を緩めると本物の不一致を隠す）。
  次作業（実フィクスチャ検証）で要否を決定
- **実フィクスチャ（本物の Audiveris 出力）の整備**: 直後の単独 /add-feature で実施
- レビュー指摘2・4（不正 duration / 空 octave の無言フォールバック）・指摘5
  （parseInt ヘルパー重複）: 別途対応
- 声部→パート帰属の推定（S1/S2 の識別）: 階名オーバーレイには不要のため実装しない

## 受け入れ条件

- [x] 和音（同 offset）で head 出現順と文書順が食い違っても、縦位置で正しく対付けされる
- [x] オクターブ重複 divisi（同レター）で座標の取り違えが起きない
- [x] backup/forward の異リズム多声で全音符が正しい符頭に対付けされる
- [x] 既存の照合仕様（音符数不一致→skipped、step クロスチェック、通し小節番号、
      多譜表分割）が退行しない（既存テスト全パス・統合テストは期待値変更なし）
- [x] 品質ゲート（test / coverage 90% / lint / typecheck / build）全パス
