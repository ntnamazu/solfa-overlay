# 設計書

## アーキテクチャ概要

コード変更を伴わない。**Git の追跡対象**と**ライセンス表記**の是正のみを行う。

判断の骨格は「**素材を差し替えるのではなく、正しく扱う**」:

```
CC BY-NC-SA 3.0 素材（IMSLP #19716 / Nancho Alvarez 編）
  │
  ├─ 原本PDF・翻案PDF・注釈JSON ──→ 【追跡から外す】
  │    理由: 翻案物は ShareAlike により MIT リポジトリの一部として配布できない。
  │          原本の再配布も、MIT を掲げるリポジトリに NC 素材を置く矛盾を生む
  │
  └─ .omr / .mxl（OMR 抽出データ）──→ 【残す・帰属表示を付ける】
       理由: 音符情報の源泉である楽曲自体は PD。版のレイアウト座標は含むが、
             回帰値の基盤であり差し替えコストが極めて高い。CC BY-NC-SA は
             帰属表示を行えば非営利での利用・再配布を許可している
```

## コンポーネント設計

### 1. `.gitignore`（除外ルールの追加）

**責務**: CC 素材とその翻案物が再びコミットされるのを防ぐ

**実装の要点**:

- 拡張子ベースで広めに除外する（`tmp/**/*.pdf`）。将来 `tmp/` に別の検証用 PDF を置いたときも自動で守られる
- `annotations.json` は個別指定する（`tmp/**/*.json` にすると設定ファイル類まで巻き込む恐れがあるため）
- **`.py` は除外しない**。既存の追跡を維持する
- なぜ除外するのかをコメントに残す。理由が書かれていない除外ルールは、後から安易に外される

### 2. `tests/fixtures/victoria/README.md`（帰属表示の追加と誤記の訂正）

**責務**: CC BY-NC-SA 3.0 が要求する帰属表示を満たし、事実と異なる記述を正す

**実装の要点**:

- CC BY が求める4要素をすべて書く: **編集者名 / 出典 URL / ライセンス名とバージョン（＋本文 URL）/ 改変した旨**
- 「改変した旨」は具体的に書く: **OMR による記号データの抽出**（`.omr` / `.mxl` の生成）と、**階名の重ね書き**
- 「作曲者 1611 年没・パブリックドメイン」という記述は、**楽曲と楽譜（版）を混同している**のが誤りの本質。両者を分けて書き直す
- 「元PDF はリポジトリに含めていない」は、**追跡除外後には真になる**。ただし理由が「数十MBあるため」となっているのは実態と異なる（実サイズは 124KB）ので、**ライセンス上の理由**へ書き換える

### 3. `docs/development-guidelines.md`（ルールの更新）

**責務**: 現実に運用できるルールへ更新する

**実装の要点**:

- 「`tests/fixtures/` に置けるのは**パブリックドメインの楽譜のみ**」は、実態（CC BY-NC-SA 素材が既に入っている）と矛盾する。ルールを実態に合わせるか、実態をルールに合わせるかの二択で、**前者を採る**（差し替えコストが高いため）
- ただし単に緩めるのではなく、**条件を課す**: 再配布可能なライセンスであること・帰属表示を README に書くこと・**原本のスキャンPDF や、そこから作った出力PDF はコミットしないこと**
- **NC 素材が混じる場合の注意**（商用利用の制約が生じる）を明記する

### 4. `THIRD_PARTY_LICENSES.md`（テスト用素材の節）

**責務**: MIT が及ぶ範囲と第三者素材の区別を、配布物のライセンス表記と同じ場所で説明する

**実装の要点**:

- 既存の構成（同梱バイナリ → 本体ライセンス）の**後ろ**に置く。配布物には含まれない情報なので、同梱物の説明と混ぜない
- **配布物（インストーラ）には含まれない**ことを明記する。テスト素材はリポジトリにのみ存在する
- NC 条項の存在を明示し、「リポジトリ全体が商用利用可能なわけではない」ことを伝える

### 5. `docs/ideas/solfa-annotation-app.md`（成果物一覧の注記）

**責務**: 追跡除外により、記載されたファイルの一部がリポジトリに存在しなくなることを明示する

**実装の要点**:

- 成果物の記述自体は履歴的価値があるため消さない。**どれがリポジトリに含まれないか**を注記で補う

## エラーハンドリング戦略

該当なし。作業上のリスクと対策のみ:

| リスク | 対策 |
| --- | --- |
| `git rm --cached` でワーキングツリーのファイルまで消す | `--cached` を必ず付ける。実行後に `ls` でファイルの実在を確認する |
| 除外ルールが広すぎて `.py` まで巻き込む | `git ls-files tmp/` で除外後の追跡状態を確認する |
| フィクスチャ本体を触ってしまい回帰値が変わる | `.omr` / `.mxl` は一切変更しない。変更するのは README のみ。`npm test` で確認する |

## テスト戦略

- **フィクスチャの実体（`.omr` / `.mxl`）は変更しない**ため、回帰値に影響は出ないはず。`npm run test` で確認する
- `tmp/` 配下のファイルはテストから参照されていない（`tests/` からの参照は README のテキスト内のみ）。追跡除外がテストを壊さないことを `npm run test` で確認する
