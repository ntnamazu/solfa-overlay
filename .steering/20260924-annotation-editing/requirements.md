# 要求内容

## 概要

楽譜プレビュー上で階名注釈を追加・編集・削除できるようにする（Issue #5 / PRD F-5 / P0）。
あわせて、楽譜プレビュー区画を Editor の最後へ移し、一覧と出力ボタンをプレビューより上に置く（Issue #17）。

## 背景

- OMR の局所的な誤りで階名が欠落した小節（スキップ小節）は、現状ではアプリ内で埋める手段がない。
  PRD の KPI「確認・修正フロー通過後の階名付与率 98%以上」「確認・修正込みで 15 分以内」は、この機能がないと達成を確認できない
- 注釈の編集 API（`addAnnotation` / `updateAnnotation` / `removeAnnotation`）と、再生成時の保全
  （`regenerateAnnotations` の `existing`）は Phase 5 で domain に先行して用意済み。UI・IPC・セッションからの結線が無い
- 楽譜プレビュー（#4）は全ページを縦に並べるため、その下にある「階名が付かなかった小節」一覧と
  「注釈付きPDFを出力」ボタンが画面のずっと下に隠れる（#4 の実機確認のフィードバック。#17）。
  #5 で Editor に編集パネルを足す前に並びを整えておくと効率がよい

## 実装対象の機能

### 1. 楽譜プレビュー上の注釈編集（#5）

- 楽譜上の階名を押すと選択され、編集パネルで文字を書き換え・削除できる
- 自動で付いた階名を書き換えた場合は「自動の階名に戻す」で上書きを取り消せる
- 楽譜上の階名の無い位置（スキップ小節の黄色い枠の中を含む）を押すと、その位置に階名を書き足せる
- 削除した直後は「元に戻す」で取り消せる（自動の階名の削除は非表示フラグのため、誤操作で戻せなくなるのを防ぐ）
- 編集結果は即座に楽譜プレビューへ反映され、自動保存・出力PDFにも反映される
- 再解析（訂正・表記の切り替え）後も手動注釈と削除フラグ・文字の上書きが保全される

### 2. Editor の区画の並び替え（#17）

- 楽譜プレビュー区画（とその直前の「階名の表記」）を Editor の最後へ移す
- 概要・スキップ小節一覧・警告・PDF出力・確認画面へ戻るボタンをプレビューより上に置く

## 受け入れ条件

### 楽譜プレビュー上の注釈編集（PRD F-5 / Issue #5 より）

- [ ] 音符数不一致等でスキップされた小節が一覧で提示され、該当箇所へジャンプできる（#4 で実装済み。回帰させない）
- [ ] 楽譜画像上の任意の位置に階名注釈を追加・編集・削除できる
- [ ] 修正結果が出力PDFに反映される
- [ ] 修正状態（注釈レイヤーの中間データ）をファイルとして保存・再読み込みできる
- [ ] 再計算後も手動注釈（`origin: 'manual'`）と削除フラグが保全される

### Editor の区画の並び替え（Issue #17 より）

- [ ] 楽譜プレビュー区画が Editor の最後の区画になっている
- [ ] 一覧・警告・PDF出力がプレビューより上にある
- [ ] Editor の区画の並び順のテストが更新されている

## 成功指標

- スキップ小節を、アプリを離れずに楽譜上で埋められる
- 追加した階名が画面と出力PDFで同じ位置・同じ文字になる（プレビューと出力の一致を構造で担保する #4 の方針を守る）

## スコープ外

以下はこのフェーズでは実装しません:

- 注釈のドラッグによる移動（位置を変えるには削除して書き足す）
- 手動注釈の変化音（紫・太字）指定。手動注釈は幹音の色で描く（音符を参照しないため変化の有無が決まらない）
- 転調点の指定・修正（F-6 / #6）
- Editor の内部識別子露出（#8）
- 左右 2 カラム・プレビューの固定高さ枠（#17 の検討案 B/C）
