# 要求内容

- 作業名: 20260720-phase5-annotation-pdf-export（ロードマップ Phase 5: 階名付与とPDF出力）

## 概要

階名計算済みの `ScoreModel` から注釈（`Annotation`）を自動生成し、元PDFの版面を変えずに
階名を重ね書きした**印刷可能なPDF**を出力できるようにする。あわせて Editor 画面の最小表示
（階名プレビュー＋出力ボタン）を実装し、PDF入力 → 階名付きPDF出力を GUI で一気通貫させる。

## 背景

ロードマップ上「リリース」の定義は **ユーザーが楽譜PDFを入力し、望む移動ド階名が付与された
印刷可能なPDFを実際に得られる状態**（F-1〜F-4 が GUI で一気通貫）である。
Phase 4 までで OMR 実行・構造解決・照合・確認フロー・調文脈・階名計算・永続化が揃い、
未実装のコンポーネントは `AnnotationManager` / `OverlayRenderer` / `writeExportPdf` の 3 つと
Editor 画面だけになった。本フェーズがリリース定義の到達点にあたる。

## 着手前の実データ計測（`tmp/probe`）

Phase 2・3・4 で 3 回連続して有効だった手順を今回も先に実施した。**4 つの発見がいずれも
設計を変えた**（計測しなければ 4 つとも実装後に事故として顕在化していた）。

### 発見1: `PageAnchor.pageIndex` は元PDFのページ番号ではない

Audiveris は 1 つの **sheet（＝元PDFの1ページ）** の中で movement 境界を検出すると
**page を分割する**。Victoria フィクスチャは 3 sheet に対し **4 page** で、
`sheet#1` が page 0（40音）と page 1（206音）の 2 ページを含む。

| フィクスチャ | sheet 数 | Audiveris page 数 | sheet あたりページ数 |
| ------------ | -------- | ----------------- | -------------------- |
| Victoria     | 3        | 4                 | 2, 1, 1              |
| divisi       | 20       | 20                | すべて 1             |

`ScoreModel` の座標が持つ `pageIndex` は Audiveris のページ添字であり、これをそのまま
PDF のページ添字として使うと **Victoria は page 1 以降の注釈が丸ごと 1 ページずれる**。
book.xml の `<sheet><input><number>` が元PDFのページ番号（1始まり）を持っており、
これを `BookPageRef` に取り込んで対応表を作る必要がある。

### 発見2: 画像寸法は sheet 単位で、A4 とは限らない

`.omr` の `<picture width height>` は **sheet 単位**（同一 sheet の複数ページは同じ画像座標を共有する）。

| フィクスチャ | picture (px) | interline (px) | 300dpi 換算 (pt)          |
| ------------ | ------------ | -------------- | ------------------------- |
| Victoria     | 2480 × 3507  | 17             | 595.2 × 841.7（≒A4）      |
| divisi       | 2408 × 3150  | 16             | 577.9 × 756.0（A4でない） |

**寸法の決め打ち（A4 前提・300dpi 前提）はできない**。元PDF から実寸を読み、
px → pt のスケールを x / y 別に求める必要がある（アスペクト比が一致する保証がないため）。

### 発見3: 符幹・加線を障害物から外すと配置品質が激変する

機能設計書の「近傍記号のバウンディングボックスとの交差を避ける」を文字どおり実装すると、
**衝突相手の 8 割が `stem`（符幹）** で、結果は実用に耐えなかった。符幹・加線は幅数pxの
細い線であり、階名文字が重なっても判読を妨げない（手書きの階名も符幹をまたいで書く）。
これを障害物から除外し、候補位置を 6 段から 10 段へ広げた結果:

計測条件は実際の描画寸法に合わせた。`DEFAULT_SETTINGS.fontSizePt = 8` は 300dpi 換算で
**33.3px** にあたり、プロトタイプ（`tmp/solfa-proto/overlay_pdf.py`）の `FONT_PX = 33` と一致する。
文字幅・高さは pdf-lib の Helvetica-Bold の実メトリクスを使った。

| 指標（符頭直上をそのまま使えた割合＝配置品質） | 設計どおり（全記号回避） | 細線を許容        |
| ---------------------------------------------- | ------------------------ | ----------------- |
| Victoria: 基本位置を採用                       | 349 / 808（43.2%）       | **721（89.2%）**  |
| Victoria: 解決不能                             | 0                        | **0**             |
| divisi: 基本位置を採用                         | 755 / 3500（21.6%）      | **2138（61.1%）** |
| divisi: 解決不能（警告行き）                   | 123（3.5%）              | **25（0.7%）**    |

設計どおりだと Victoria は**注釈の 57% が符頭の真上から追い出される**（多くは符頭の下へ回る）。
細線を許容すると 9 割が本来の位置に収まり、divisi の配置不能も 1/5 になる。

**副産物**: 注釈の高さはフォントの em 全体ではなく**アセンダ高**（`heightOfFontAtSize(size,
{descender: false})` = 0.718em）で判定するのが正しい。階名の音節は小文字のみでディセンダを
持たないため、em 全体で判定すると divisi の解決不能が 25 → 54 件に倍増する。

### 発見4: 実データに pdf-lib 標準フォントで描けない音節が出る

`syllableFor` は表にない変位を `do♯` `l♭` のようにフォールバック表示する。
`♯`(U+266F) / `♭`(U+266D) は **WinAnsiEncoding でエンコードできず pdf-lib が例外を投げる**
（`WinAnsi cannot encode "♯" (0x266f)`）。これは理論上の話ではなく実データで発生する:

| 設定           | Victoria | divisi                                |
| -------------- | -------- | ------------------------------------- |
| kodaly（既定） | 0 件     | `do♭`×3 / `ti♯`×1（計 4 件）          |
| tonicSolfa     | 0 件     | `l♭`×51 / `d♭`×3 / `t♯`×1（計 55 件） |

1 文字でも混ざると **PDF 出力そのものが失敗する**（部分的な劣化ではなく全滅）。
描画時に ASCII へ置換する経路が必須。

## 実装対象の機能

### 1. ページ対応表の確定（`PageInfo` の実値化）

- `BookPageRef` に元PDFページ番号（`<input><number>`）を追加する
- 元PDF（pdf-lib）のページ寸法・回転と `.omr` の画像寸法から `PageInfo` を組み立てる
- Audiveris ページ → 元PDFページの対応と、px → pt のスケール係数を確定させる

### 2. `AnnotationManager`（注釈の自動生成と衝突回避）

- 階名の付いた `ScoreModel` から `layer: 'solfa'` の注釈を生成する
- 手動注釈（`origin: 'manual'`）と削除フラグ（`deleted`）を再生成でも保全する
- 配置は符頭直上を基本とし、交差する場合は候補位置の梯子から空きを探す
- どの候補も空かない注釈を「配置警告」として報告する
- スキップ小節の一覧を返す（Editor のジャンプ先）

### 3. `OverlayRenderer`（注釈付きPDFのバイト列生成）

- 元PDFを再エンコードせず、pdf-lib でページに文字を追記する
- `.omr` px → PDF pt の座標変換（y 軸反転・ページ回転の考慮）
- 幹音＝濃赤 / 変化音＝紫のカラーコーディング（設定から取得）
- 標準フォントで描けない文字の置換

### 4. `writeExportPdf`（storage）

- 一時ファイル → リネームによる原子的書き出し

### 5. Editor 画面の最小表示と PDF 出力の結線

- 階名プレビュー（パート×小節の階名列）・スキップ小節一覧・配置警告の表示
- 「PDF出力」から保存先を選び、注釈付きPDFを書き出す
- 承認前（`completedAt === null`）は出力させない
- Phase 4 からの申し送り「`unmatchedCorrections` を画面が表示していない」を解消する
